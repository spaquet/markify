Markify 2.0.0 and 2.0.1 don’t open

Fixed in 2.0.2 Issue #49

What you see

You double-click Markify and nothing happens: no window, no error, no crash report, and Markify doesn’t appear in Activity Monitor. Only its Quick Look extension (MarkifyQuickLook) runs. Reinstalling doesn’t help.

What happened

Version 2.0.0 added the markify command-line tool. When the release was packaged, the tool was copied to Contents/MacOS/markify, next to the app’s own program Contents/MacOS/Markify. On a Mac’s default, case-insensitive disk those are the same file, so the command-line tool replaced the app. Opening Markify ran the tool, which printed its help text and quit.

The bug was in the release packaging only: Gatekeeper, your settings and how you installed Markify had nothing to do with it. Builds made in Xcode were never affected, which is why it slipped through.

How to fix it

Markify can’t update itself from 2.0.0 or 2.0.1, because it never starts. Install 2.0.2 by hand; your documents and settings are kept.

  1. Download Markify 2.0.2 from the release page or the download section: markify-as.dmg for Apple silicon, markify-intel.dmg for Intel.
  2. Drag Markify to Applications and choose Replace.
  3. Open Markify. On 1.90 or earlier? Use Markify › Check for Updates… instead; it installs 2.0.2 directly.

If you use the command line

The markify tool now lives in Contents/Helpers. If you linked it into your PATH, update the link:

ln -sf /Applications/Markify.app/Contents/Helpers/markify /usr/local/bin/markify

The Claude Code, Codex and OpenCode plugins find the new location on their own after you update them. See Command line.
