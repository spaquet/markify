# Design decisions

- Markify opens an empty document on launch. The document picker remains available through File > Open, matching the empty-document design state.
- Saved image drops copy into `assets` beside the Markdown file. Name collisions get a numeric suffix; unsaved documents use the original absolute path until saved.
- A library defaults to `~/Documents/Markify` when that folder exists. Settings can choose another folder with a persistent security-scoped bookmark.
- The source remains plain Markdown. Both lenses style the same TextKit 2 text storage, so selection offsets and undo history stay in source coordinates.
- Directly distributed Markify builds disable App Sandbox in both Debug and Release, so local images, linked documents and summaries need no folder grants. Hardened Runtime remains enabled. Quick Look stays sandboxed and uses a private, unsandboxed XPC helper that returns only validated images referenced by the previewed Markdown, with bounded reads and a check of the connecting extension's code signature. Release signing preserves the extension's sandbox entitlements.
- Display math uses SwaTex's native CoreText renderer; formulas render locally without a WebView.
- Ordered lists display counted numbers in the rendered lens; the file keeps its written numbers until an edit touches that list, which then renumbers only that list.
- Settings › On launch drives startup instead of system window restoration: "Reopen last documents" reopens the files open at quit (security-scoped bookmarks), "New document" opens an empty document, and "Library" opens an empty document with the library sidebar showing.
- "New documents are saved to Library" starts an untitled document's save panel in the library folder; the panel still asks for a name.
- "Reload when changed on disk" was dropped from Settings. The system document architecture already reloads unedited documents, and SwiftUI's `DocumentGroup` offers no clean way to turn that off.
- The per-document lens is stored in the `com.markify.lens` extended attribute and rewritten when the window closes, since saves can replace the file.
- "Use surrounding section as context" sends the heading-bounded section around a selection or the caret with the request; when off, selection edits see only the selection and caret generation sees the whole document.
- Proofread (2b) stays with the system Writing Tools, which already underline suggestions in place. Markify's own selection edits (tones, Describe your change, Summary, Key Points, List, Table) use the 2c review: the result replaces the selection as one undo step inside an AI edge, with Try Again, Compare, Discard Rewrite and Accept (⌘↩). Esc discards the rewrite; typing accepts.
- The generate composer (2d) floats in the column below the caret and shows output inside the composer rather than streaming it into the file, so nothing is written until Keep.
- Footnote references show their text in the system tooltip, not a custom glass popover.
- Frontmatter collapses to a chip row in the Rendered lens; clicking a chip edits the YAML in a native popover and writes it back as one change.
- Settings choices where the spec gave no option list: prose font New York / SF Pro, Markdown font SF Mono / Menlo, page color Paper / White / System, code theme Match appearance / Monochrome, pasted images to ./assets / ./images / the document's folder.
- Shortcuts are stored as overrides of the defaults. Recording a key another action uses moves it and leaves that action unassigned. ⌘+ also zooms in alongside the configurable ⌘=.
- The Welcome document is copied into the library as "Welcome to Markify.md" on first launch and can be reopened from Help.
- OKF (Open Knowledge Format) support lives in the local `OKFKit` package (Yams for reading YAML, never for writing). Frontmatter edits splice only the touched key, so comments, key order and unknown keys survive. See OKF.md.
- OKF badges (type, status, stale, trust, resource) join the existing frontmatter chip row only when the frontmatter has a `type`; plain notes are unchanged.
- ⌘-click follows links in both lenses; `/…` links resolve against the OKF bundle root (nearest `index.md` with `okf_version`, else the library, else the file's folder). A missing `.md` target offers to create it as a concept.
- The right Links panel reads ordered link spans from the editor's Markdown model and uses source offsets for navigation. It fetches a web page only after “Fetch and summarize”; local Markdown and web summaries use Apple Intelligence on demand. An app-owned Application Support JSON file stores summaries by normalized destination URL with a source fingerprint and generation date, leaving the Markdown and undo history untouched. Local targets are checked for changes when the panel opens; web summaries persist until explicitly refreshed.
- `index.md` and `log.md` are written only through Knowledge menu commands, never automatically.
- AI frontmatter suggestions merge key by key instead of replacing the block. In OKF concepts they add `description` and, only when missing, `type`. Keeping AI text in a concept stamps `generated.by` as `apple-intelligence/macos-<major>.<minor>`; the on-device model ships with the OS, so its version names the model.
- Open Bundle Folder… keeps a security-scoped bookmark per bundle; a granted folder counts as a bundle even without `okf_version`.
- Typing in an OKF concept's body stamps `generated.by: human:<id>` after two idle seconds, at most once a day, and never for undo, redo, frontmatter-only or AI edits. After Rename or Move To, Markify asks before rewriting links in other files.
- The editor reads Markdown from one parse per text version (`MarkdownModel` in the `MarkifyMarkdown` package, built on swift-markdown/cmark-gfm) instead of per-syntax regular expressions, so styling, drawing, clicks and list/table editing agree with CommonMark and GFM. Frontmatter, math, footnote definitions and MDX blocks are masked with same-length whitespace before parsing, so offsets still point into the source.
- CommonMark rules apply as cmark reads them: `text` over `---` is a setext heading, text indented four spaces is code, `~~~` fences are code, unclosed fences run to the end, nested task items get checkboxes, and an ordered list not starting at 1 cannot interrupt a paragraph. `/Divider` inserts a blank line first when text sits right above it, so it never makes a heading.
- Tables follow GFM: outer pipes are optional, a pipe inside a code span still splits the cell (write `\|`), and cells past the header's count are dropped.
- Inline math follows Pandoc's dollar rules: no space inside either `$`, and no digit right after the closing one, so "$5 and $10" stays text.
- The Markdown lens follows the design: all syntax in ink3 (including task boxes and table pipes), link and image destinations in accent, link text in ink. The Rendered lens draws HTML blocks and inline images while keeping their source in the same text storage; the Markdown lens shows the HTML source.
- Hidden markers kern each character by its own advance; a single kern could not cancel a long marker and left gaps after links, emphasis and code.
- ⌘-click on a footnote reference selects its definition; ⌘-click on the definition's label returns to that reference, or to the first one when edits moved it.
- Dropping a note from the sidebar or Finder into the page inserts `[title](path)`: relative to the document, bundle-absolute (`/…`) when both notes are in its OKF bundle, absolute while the document is unsaved. There is no Copy Markdown Link menu.
- Remote images load when Settings › Load remote images is on (the default); the app has the outgoing network entitlement for them. Loading reveals to the image host that the note was opened. Inline images show as a chip with the alt text and preview on hover; images alone on a line keep the full-width block.
- Fenced `mermaid` blocks render as diagrams in the Rendered lens with the bundled Mermaid 12.0.0 (MIT) in an offscreen WKWebView that allows no network access or navigation. They sit in the code block container, follow light/dark, and scale to the column. A block Mermaid cannot parse stays visible as code with Mermaid's message below it.
- `.mdx` files open as Markdown. Top-level `import`/`export` blocks and JSX blocks are dimmed like HTML and never rewritten; `{expressions}` stay plain text.
- Rendered-lens decorations are drawn by the paragraph's `NSTextLayoutFragment` (`MarkdownLayoutFragment`), from rendering attributes `style()` sets, instead of an overlay view positioned from character rects. Decorations then move with their text through layout, scrolling and resizing. The architecture follows [nodes-app/swift-markdown-engine](https://github.com/nodes-app/swift-markdown-engine) (Apache-2.0); Markify does not depend on that library or copy its code. Table cell fields stay views, placed from layout-manager rects.
- Code blocks and callouts in the Rendered lens are one rounded box across their lines (code: radius 12, 16×18 padding; callouts: radius 14, 14×18 padding), as in the design, with the code language label in the top padding. Selected text inside a box stays visible. The Markdown lens keeps the plain code background.
- Updates use Sparkle 2 with the appcast attached to each GitHub release (`releases/latest/download/appcast.xml`), so publishing a release is the only step and nothing is committed to the site. One universal `markify-update.zip` serves both architectures; the DMGs stay per architecture. Automatic checks are on by default (`SUEnableAutomaticChecks`), so Sparkle doesn't ask on second launch; automatic installs are off until turned on in Settings › General › Updates. Release notes are the GitHub release's Markdown.
- Export renders HTML from `MarkdownHTML`, which reads extensions with the same scan as `MarkdownModel`, instead of swift-markdown's `HTMLFormatter` (which escapes nothing and knows no extensions). The HTML is one self-contained file: local images become data URIs, math is SVG with glyph outlines (no web fonts), Mermaid diagrams are SVG in the light theme on a white card, relative links are rewritten for the export's folder, and GFM's literal quotes and dashes are kept (no smart punctuation). Frontmatter shows as the date and tag chips only.
- PDF export prints the HTML page with WebKit on the default paper size, rather than snapshotting the text view, so it paginates and matches the HTML. Its page carries a Content-Security-Policy: no scripts from raw HTML, and remote images only when Settings allows them.
- Help is an Apple Help Book built from `help/*.md` (it opens in Tips on current macOS), so the Help menu's search finds it offline. The same Markdown builds the website's help, FAQ and legal pages. The website's copy is published with each release, not on every change to `help/`.
- The About window replaces the standard panel: icon, version and build, links to the website, GitHub, releases and sponsorship, and a one-line credit that links to the Legal help page, which holds the license, privacy statement and third-party credits.
- The first-launch Welcome tour is copied into the library once. A later version replaces the copy only when it is byte-identical to a tour Markify shipped (hashes in `MarkifyAppDelegate.previousWelcomes`); an edited copy is never touched. `markify://welcome` opens it, for links from the help.
- The Legal page shows the LICENSE built in at generation time and, on the website, refreshes it from the repository with a script, so it always matches GitHub while still working without JavaScript.
- Inline `$…$` math is typeset in the Rendered lens with SwaTex at the size of the surrounding text, drawn as vectors on the line's baseline by the layout fragment. Its source is hidden like a marker, and the opening `$` keeps the text's font and reserves the formula's width, so a line holding only a formula keeps its height. While the caret or selection touches a formula, it shows as LaTeX with dimmed dollars for editing; moving in or out restyles.
- Scripted workflows use a separate `markify` Swift executable bundled in `Markify.app/Contents/Helpers` (not `Contents/MacOS`, where on a case-insensitive volume `markify` would replace the app executable `Markify`), so `check` and `export` run without an editor window. `check` reuses `OKFKit` and fails only on error diagnostics or unreadable input; warnings and information are printed. `export --html --output` requires distinct input and output paths and uses the shared `MarkdownPage` builder for page markup, local images and link rewriting. The CLI leaves PDF export and app-only rendering hooks (math SVG, Mermaid SVG and code colors) to the app until headless packaging of those renderers is justified. The release workflow builds the CLI for each app architecture before signing and packaging.

- The Links panel groups occurrences by the existing normalized summary-cache destination key, retaining first-occurrence order and clickable source lines. Expansion follows the destination across edits. Read-only native text views provide partial selection and the standard copy actions for summaries and messages.
- Quick Look uses a view-based `QLPreviewingController` with a script-disabled WKWebView so link clicks can be intercepted and failures shown in the preview. The existing signed-client XPC helper checks that a local Markdown destination is referenced in the current source before asking NSWorkspace to open it in Markify. The extension remains sandboxed, and its entitlements do not change.
- The right pane holds Contents and Links behind a native segmented control, remembered across windows (`documentPanelTab`), until the #52 redesign. Contents lists level 1 and 2 headings (ATX and setext) from the shared Markdown model in source order; titles drop inline markers and inline HTML, level 2 headings under a level 1 heading are indented, and repeated titles stay separate entries keyed by source offset. Choosing one (or a link) moves the caret there and scrolls that line to the top of the page even when it is already visible, so every jump looks the same; it only changes the selection, so the source and undo history are untouched.
- The text column is fluid instead of the design's fixed 640pt: it fills the page between margins of 5% a side (16–96pt), so widening the window widens the text and the margins grow in proportion, the way Notes and TextEdit wrap to the window. Settings › Editor › Limit line width (off by default) restores a fixed maximum measure, 560–1200pt, for readers who want shorter lines. Both side panes slide over the page as the design specifies and never move or resize the text; a click on the page closes them.
- The Sentry DSN comes from the `SENTRY_DSN` build setting through the `SentryDSN` Info.plist key: the git-ignored `Config/Sentry.local.xcconfig` for local builds, the `SENTRY_DSN` repository secret for CI. Builds without one start no Sentry. Debug builds report to the `development` environment and Release builds to `production`, so one Sentry project separates testing from users by filter.
